Get started

Know which AI agent wrote each line. Undo just theirs.

Three agents and two people work in one repository. git blame can only name whoever committed. DeepBlame names the agent, what it was asked for, and what it cost — and takes one agent's work back out without losing anyone else's.

$ npx deepblame init

git blame names a person. Nobody wrote this code.

A commit says a human made it. It cannot say which tool typed it, what it was asked to do, or what it read first. Every vendor keeps its own history, and none of them covers the others. DeepBlame keeps one record for all of them, in your own repository.

blame

Which agent wrote this line, with a confidence you can check.

A line is claimed only when it can be followed from the state the run left to the file as it stands now. Anything else is reported as unknown rather than guessed at. It survives edits elsewhere in the file, follows the file through renames, and keeps the line at a lower confidence when a formatter reindents everything — and says so.

revert

Take one agent's work back out. Keep everyone else's.

An agent adds a retry loop to upload.ts. You rename the export in the same file. Revert takes the retry loop out and leaves your rename standing. A plain three-way merge cannot do that — two changes on adjacent lines conflict — because DeepBlame has something git does not: a record of which lines belong to the agent.

Nothing is written without --apply. A file that moved on too far is reported, not mangled.

revert --agent claude-code
$ deepblame revert --agent claude-code

Undoing 1 run by claude-code  ~/code/app

  ✓ src/upload.ts  3 lines        comes out cleanly
  · src/index.ts   12 lines       changed again after the agent

Nothing has been written yet.
Add --apply to undo 1 file.

cost

What the agents actually spent, per turn and per model.

Read from the agent's own session log. Where the agent reports its own price, that figure is used instead of ours. A model with no known rate is left blank rather than guessed at — a missing number is honest, an invented one is not.

Across the team

Push your runs, pull everyone else's. Joining two ledgers cannot conflict by construction, and the file contents travel too — so blame and revert work on a colleague's agent from your own machine.

$ deepblame push
Sent the ledger to origin.
  12 runs, 3 came in first.

$ deepblame pull
4 runs came in from origin.

Every command.

One setup, then four commands answer nearly everything. No dashboard to learn, no account to make.

deepblame initSet up the ledger, local state and capture hooks
deepblame blame <file>Which agent wrote each line, and how sure we are
deepblame revertUndo one agent's work and nobody else's
deepblame costWhat the agents spent, by model and by agent
deepblame reportHow much of a branch or pull request an agent wrote
deepblame push / pullShare the ledger with your team
deepblame log / showEvery recorded run, and one run in full
deepblame doctorCheck recording is working, and say what to fix
deepblame gcAge old file contents out of the ledger

It never sends anything anywhere.

The ledger lives in a git ref in your own repository, refs/deepblame/ledger. It is never checked out, so your branches, working tree and index stay exactly as they were, and it is never signed with your key — a signing prompt can never block an agent. Prompts stay on your machine unless your team turns that on. There is no account, no server and no telemetry, and the whole thing is Apache-2.0 on GitHub.
