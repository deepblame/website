how it works you

git blame names a person. Nobody wrote this code.

Three agents and two people work in the same repository. A commit says a human made it. It cannot say which tool typed it, what it was asked to do, or what it read first. Every vendor keeps its own history, and none of them covers the others.

  1. Set it up once

    Creates the ledger in its own git ref and wires up the agents it finds in the project. Your branches, working tree and index are never touched.

    $ npx deepblame init

  2. Your agents work as usual

    Every prompt, tool call and edit is appended to a local queue in about 40 milliseconds. No git process, no network, and it always exits zero. When the turn ends, the queue becomes one run in the ledger.

    Nothing showing up? deepblame doctor says why, and what to do about it.

  3. Ask the ledger

    Who wrote a line, what a week of agent work cost, and what happens if you take one agent's work back out. The record is local, append-only, and yours.

One ledger, every tool

Claude Code and OpenCode in full, Codex turn by turn, everything else at commit level.

Evidence, not guesses

A line is claimed only when it can be followed from the state the run left to the file as it stands.

Append-only

Written with git plumbing to its own ref. Never checked out, never signed with your key.

blame claude-code feb92f2

Which agent wrote this line, with a confidence you can check.

The percentage is not decoration. It says how the line was followed from the run that wrote it to the file as it is now, and it holds up when the file changes around it.

RenamedFollowed, and it says what the file used to be called
A formatter reindented it70%, only the spacing changed
Somebody rewrote the lineNot claimed at all
Merged from a branchThe agent keeps it. A merge writes no lines

Undo one agent's work. Keep everyone else's.

Checking the file out as it was would throw away everything written since. The ledger knows which lines the run changed, so those are the lines that come back out.

before
An agent adds a retry loop to upload.js.
then
You rename the export in the same file.
revert
The retry loop is gone. Your rename is still there.

A plain three-way merge cannot do that. Two changes on adjacent lines conflict, and between an agent and a person that is most of the time. DeepBlame has something git does not: a record of which lines belong to the agent.

~/code/app
$ npx deepblame revert --agent claude-code

Undoing 1 run by claude-code  ~/code/app

  ✓ upload.js  3 lines  comes out cleanly

Nothing has been written yet.
Add --apply to undo 1 file.

Nothing is written without --apply. Conflicts are shown first. A file the agent created but you have edited since is never deleted for you.

agents git (Yusuf)

It works with the tools you already use.

Claude Code, Cursor and OpenCode are recorded tool call by tool call. The fallbacks are coarser on purpose, and they say so. When a hooked agent and a commit both touch a line, the agent we actually watched keeps the credit.

ToolSet up withWhat you get
Claude Codeinit, automaticallyEvery prompt, tool call and edit, with model and cost
Cursorinit, automaticallyEvery prompt, read and edit, with the exact strings it replaced
OpenCodeinit, automaticallyThe same, with the tokens and price OpenCode itself reports
Codexhooks install --agent codexOne run per turn, with the files it changed
Copilot, Windsurf, anythinghooks install --agent gitOne run per commit, with the lines it changed

There will always be a tool we have not heard of, so there is a documented way in: one JSON object per call on stdin. No SDK, no dependency, nothing to keep in step with our releases. Our own OpenCode plugin is forty lines on top of it.

commands you

Eleven commands, and that is the whole surface.

Run any of them with --json for machine-readable output, or -C <dir> to work in another directory.

CommandWhat it does
deepblame initSet up the ledger, local state and capture hooks
deepblame statusShow what is set up and what is being recorded
deepblame logList recorded agent runs, newest first
deepblame show <run>Show one run in full: prompt, tools, files, cost
deepblame blame <file>Which agent wrote each line, and how sure we are
deepblame costWhat the agents spent, by model and by agent
deepblame revertUndo one agent's work and nobody else's
deepblame doctorCheck recording is working, and say what to fix
deepblame gcAge old file contents out of the ledger
deepblame sealFold captured events into the ledger now
deepblame hooksInstall, uninstall or check the capture hooks

privacy you

Nothing leaves your machine.

No network calls. The capture hook spawns no git, opens no socket, and always exits zero. A recorder that can fail a build is a recorder people turn off.

Prompts are stored as hashes. The text itself is recorded only if you turn it on in .deepblame/config.json.

Apache-2.0, and the whole thing is readable. A tool that watches everything you write has no business being a black box.
